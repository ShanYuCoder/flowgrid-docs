# Skill: `/user-flow`

**SSOT 準拠元：** `harness/docs/skills/user-flow/SKILL.md`

画面 (`W-*`) と API (`API-*`) を結びつける包括的な業務ロードマップとして、エンドツーエンドのユーザー業務フロー (User Flows) を設計する中核スキル。

- 成果物仕様書：`architecture/03-user-flows/` または `**/common/user-flows/` 配下の `FLOW-*.md`。
- 命名規則：`FLOW-{SURF}-{DOMAIN}-{NN}`（例：`FLOW-ADM-AUTH-01`）。独自ルールによる無秩序な命名は厳禁。
- 自動監査：`flowgrid audit flow <path>`。

---

## 中核ユーザーフロー分類

1. **複数ステップの業務ウィザード (Multi-step Journeys)：** チェックアウト購入手続き、多段階アカウント開設ウィザード。
2. **エンティティ状態遷移マシン (State Machines)：** 注文ライフサイクル状態遷移、多段階稟議承認フロー。
3. **ロール・権限分岐 (Role Branching)：** 一般ユーザーと管理者で厳密に分岐する操作パス。
4. **非同期処理・Webhook (Async / Webhooks)：** 決済代行コールバック、バックグラウンドでの非同期バッチ処理。
5. **ダイアログ・サブフロー (Dialog Sub-flows)：** 複数画面にまたがるドロワーやモーダルダイアログの対話フロー。

---

## 階層分離 vs モノリシック仕様書の誤謬 (Monolithic Spec)

- **モノリシック仕様書パターンの誤謬 (Monolithic Spec Fallacy)：** 複数の画面、フォーム、API を 1 つの巨大な単体仕様書に詰め込むと、ユーザーフローが埋没します。AI Agent はコンテキスト飽和に陥り、画面間のデータ受け渡し、競合状態、部分障害時のロールバック処理を見落とします。
- **FlowGrid の階層分離アーキテクチャ：**
  - **マクロ統合層 (`FLOW-*.md`)：** 業務アクター、画面 (`W-*`)、API (`API-*`)、業務ルール (`BR-*`)、非同期ワーカーを結ぶ高水準ロードマップ。
  - **ミクロ原子層 (`W-*.bundle.yaml`)：** **単一画面**に鋭くフォーカス：レイアウト構成、テーブル列定義、項目バリデーション、および単一画面内の対話状態 (`interactionCases` L2)。

## 5 大エッジケース盲点チェックリスト

1. **画面再読込・戻る操作と状態消失：** 明示的な永続化モード（URL クエリパラメータ、`sessionStorage`、サーバー下書き Draft ID）を定義。
2. **並行更新と競合状態 (Race Conditions)：** 楽観的ロック（`version` / `updated_at`）、冪等性キー (Idempotency Key)、`409 Conflict` 解決プロトコルを定義。
3. **画面間ハンドオフと通知障害の救済：** 受信側にフォールバック用の未処理キュー (Worklist Queue) を定義し、通知失敗によるタスク孤立を防止。
4. **部分障害と Saga 補償トランザクション：** シーケンス図の `alt/else` ブロックに補償ロールバック（自動返金、在庫引当解除）を明記。
5. **受け渡しデータのスキーマ乖離：** 送信元画面の出力ペイロードと遷移先画面の入力 Props 契約を項目単位で照合。

## クロスフロー深度分析プロトコル

- **Tier A (画面領域横断 Cross-Surface)：** $\ge 2$ つの異なるランタイムまたはアクター間の連携（顧客 Web ➔ 管理画面 Admin ➔ バックグラウンドワーカー）。項目単位のペイロード互換性、冪等性キー、Saga 補償トランザクションを完全監査。
- **Tier B (画面領域内共通 Surface-Shared)：** 同一サーフェス内の複数モジュールで共通利用される業務ジャーニー（安全なエンティティ削除、一括データエクスポート）。
- **Tier C (モジュール内ローカル Module-Scope)：** 単一コンポーネントクラスタ内の局所的ジャーニー（3 ステップ作成ウィザード）。

## 図表選定デシジョンマトリクス：何をいつ描くべきか

| 図表タイプ | Mermaid 記法 | 適用シナリオとタイミング | 必須の構成要素 |
| :--- | :--- | :--- | :--- |
| **シーケンス図 (Sequence Diagram)** | `sequenceDiagram` | $\ge 2$ つのライフラインにまたがる時系列の動的相互作用（アクター、フロント、ゲートウェイ、バックエンド、DB、ワーカー、外部連携）。 | `autonumber`、`alt/else` 異常系分岐、`rect` 非同期ワーカーブロック、`-->>` 明確な返却応答。 |
| **フローチャート / ブロック図 (Flowchart)** | `flowchart TD/LR` | 複雑な条件分岐ツリー (`IF/ELSE` 分岐)、画面遷移ルーティング図、データ処理パイプライン。 | `([開始/終了])`、`{条件判定?}` 菱形ノード、ラベル付きエッジ (`-->|はい|`)。 |
| **状態遷移図 (State Machine)** | `stateDiagram-v2` | エンティティライフサイクルの状態遷移（例：注文 `DRAFT ➔ PENDING ➔ PAID / CANCELLED`）。 | `[*] --> 初期状態`、遷移ラベル (`イベント [ガード条件]`)、終了状態。 |
