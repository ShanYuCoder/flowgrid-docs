# `/manual`

The `/manual` skill generates End-User Documentation (User Manuals / Help Center Guides) based on finalized Specs and Automation E2E Evidences. It is primarily used after the Prototype and QA (Testcase) phases are completed to ensure that user-facing documentation accurately reflects the validated interface and business rules.

## Capabilities

- **Flow-Centric Context:** Generates the manual based on User Flow (`FLOW-*`) documents, focusing on the user journey and alternative branches rather than static screen fields.
- **End-User Narrative:** Discards granular technical validations (like max-length or regex) and translates instructions into narrative, task-oriented language (e.g., "Step 1: Go to Central Admin").
- **Evidence Integration:** Automatically links to real screen captures generated by the Automation E2E test suite (e.g., Playwright/Cypress evidence in `qa/e2e/evidence/`).
- **Standardization:** Generates files according to the standard template `surfaces/_user-manual-page.template.md`, strictly segregating them from technical specifications by placing them in `surfaces/<surface-name>/user-manuals/<module-name>/`.

## Usage

Generate a manual for a specific user flow (recommended):
```bash
flowgrid docs /manual FLOW-ADM-TENANT-SETUP
```

Generate manuals for an entire module's flows:
```bash
flowgrid docs /manual CMP-ADM-TENANT
```

## Workflow Context
This skill bridges the gap between technical delivery and operational handoff. Because it uses E2E Test Evidences as the source for screen images, it guarantees that the User Manual is never out-of-date as long as the test suite is running successfully.
